## Key decisions already made — don't re-litigate without reason
1. **Excel (.xlsx), not CSV**, for every input/intermediate/final-output
   file, per Ramesh's explicit request — he wants native Excel charts he
   can walk through on camera.
2. **No native Excel "PivotTable" objects** — openpyxl/pandas cannot create
   those cross-platform (the only way is Windows-only COM automation via
   `win32com`, which won't run on the Mac this gets recorded on anyway). The
   shipped alternative: pre-aggregated summary sheets + **real embedded
   openpyxl charts** (`BarChart`/`LineChart`), fully rebuilt every time the
   `02_*.py` script runs — this was explained to and accepted by Ramesh.
3. **A real `.pbix` can't be hand-authored as text** — only Power BI
   Desktop can produce one. Ramesh chose (via AskUserQuestion) the
   "build guide, self-execute" path over live pairing or browser
   automation against Power BI service — so `powerbi_build_guide.md` is
   the deliverable, not an actual `.pbix` file. Don't attempt browser
   automation against his Power BI account without him explicitly asking
   again.
4. **Use case 1 (NLP) uses NO LLM API** — a hand-curated keyword dictionary
   (bootstrapped fast via a TF-IDF/CountVectorizer frequency scan over
   low-CSAT responses, not days of manual reading) + VADER lexicon
   sentiment, both fully offline. There's a disabled, clearly-commented
   "Cell 11" in `02_root_cause_sentiment_analysis.py` showing where an LLM
   API would plug in once/if approved — don't enable it without Ramesh's
   go-ahead.
5. **Use case 2 (forecasting) uses classical stats, no API**: Holt-Winters
   exponential smoothing (statsmodels), benchmarked against a naive-seasonal
   baseline on a 60-day holdout before being trusted.
6. **The synthetic data was deliberately tuned, twice, after catching real
   bugs** — don't undo this tuning without re-testing:
   - Use case 2's noise level is `0.24` (in `01_generate_synthetic_data.py`,
     the `noise = rng.normal(1.0, 0.24)` line) and the roster is `40` agents
     — both tuned so that (a) Holt-Winters genuinely beats the naive
     baseline (it did NOT at lower noise — verified via a parameter sweep),
     and (b) a real, modest staffing gap shows up (~1–2 FTE short on ~30/42
     days) instead of either "no story" (overstaffed) or an unbelievable
     crisis. If you ever change `RANDOM_SEED`, roster size, or noise, rerun
     and check `02_demand_forecasting.py`'s own `assert hw_mape < baseline_mape`
     doesn't fail, and sanity-check `days_short` isn't 0 or absurdly high.
   - Use case 1's driver weights/correlations (channel, LoB, tenure) in
     `pick_driver()` were tuned so the "story" (Billing is #1 driver, newer
     agents skew toward Agent Behavior complaints, Voice skews toward
     Agent Behavior/Resolution complaints) actually shows up in the output
     — verified via a real run, not just code-reading.
7. **Narration scripts deliberately exclude Ramesh's personal introduction**
   — he said a scripted intro "would be wrong if the narration goes to
   them." Never add one; that part is intentionally left for him to say in
   his own words, unscripted.
8. **GitHub repo name**: `ds-video-task-use-cases`, deliberately generic —
   doesn't reveal Concentrix/Mercor in a public URL. Chosen by Ramesh from
   an AskUserQuestion menu.
