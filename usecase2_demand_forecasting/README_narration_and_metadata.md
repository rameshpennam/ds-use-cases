## Setup (before recording — not part of the recorded take)
```
pip install -r requirements.txt
python 01_generate_synthetic_data.py
```
This creates `input/input_call_volume_history.xlsx` and
`input/input_agent_roster.xlsx`. Then open `02_demand_forecasting.py` in VS
Code and do one silent dry run of every cell so you know what each one
prints/plots before recording. The final cell produces one workbook,
`final_output/final_output_forecast_staffing.xlsx`, with 2 sheets and 2
embedded charts — rebuilt from scratch every time the script runs.

**Known result on the shipped synthetic data** (so you know what to expect,
not a guarantee if you change the random seed/config): Holt-Winters beats the
naive-seasonal baseline (~18.8% vs ~20.1% holdout MAPE), and the current
45→40-agent roster runs short by roughly 1-2 FTE on most days over the next
6 weeks — a believable, actionable "we're tight, not in crisis" story. If you
regenerate the data and the model ever loses to the baseline, the script's
own `assert` will stop you before you present a false "the model is better"
claim — that's intentional, see `narration_script.md` for how to talk about it
either way.

## Metadata.rtf content (paste this into Metadata.rtf before upload)
**Task**: Build a daily contact-volume forecasting model and translate it
into required agent staffing (FTE), compared against current roster
availability.
**Apps used**: VS Code (Python), Microsoft Power BI Desktop.
**Request / scenario**: As a data analytics consultant, forecast customer
care contact volume for the next 6 weeks from ~3.8 years of daily history
(with trend, weekly/yearly seasonality, holidays and campaign spikes), then
convert the forecast into required agent FTE and flag staffing gaps against
the current roster.
**Flow**: Generate/ingest 3+ years of volume history + agent roster →
exploratory decomposition (trend/seasonality) → naive baseline forecast →
Holt-Winters exponential smoothing model → validate on a holdout → forecast
forward 6 weeks → convert to required FTE via handle time + occupancy →
compare to available roster hours → export one Excel workbook (2 sheets, 2
charts) → build a Power BI report for the staffing narrative.
**Output**: `final_output_forecast_staffing.xlsx` (Forecast_Staffing,
Insights sheets), plus a Power BI report (3-4 visuals) built live on screen.

## Notes on scope / assumptions (say this out loud if asked)
- Forecast is built at the total-daily level for clarity in a single
  walkthrough; a production rollout would model each LoB/channel series
  separately — the output file still carries enough detail to slice by LoB
  in Power BI from the raw input if needed.
- Staffing conversion uses a simple occupancy-based formula
  (`hours = volume × AHT / 3600`, `FTE = hours / (shift hours × occupancy)`).
  A full rollout would use Erlang C for service-level-driven staffing — noted
  as a next step, not built here, to keep the walkthrough explainable on
  camera.
