## Setup (before recording — not part of the recorded take)
No virtual environment needed — this runs on a dedicated single-purpose
recording account, so there's nothing for package versions to conflict
with. Just install straight into your user profile:
```
# Windows (PowerShell)
pip install --user -r requirements.txt
python 01_generate_synthetic_data.py

# macOS (Terminal)
pip3 install --user -r requirements.txt
python3 01_generate_synthetic_data.py
```
`--user` avoids needing admin rights. Run this once as early as possible
(ideally the moment you get the Mac, not for the first time on recording
day) so any network/firewall issue surfaces before you're on camera.

This creates `input/input_call_volume_history.xlsx` and
`input/input_agent_roster.xlsx` (40 agents, incl. a real `shrinkage_pct`
column). Then open `02_demand_forecasting.py` in VS Code (Python extension)
and run it **cell by cell** — click the "▷ Run Cell" link above each `# %%`
block, or Shift+Enter (runs + auto-advances). Do one silent dry run of
every cell before recording. The first cell you ever run in a session takes
~5-15s to start its Python kernel — run that once before you hit record.
The script produces one workbook,
`final_output/final_output_forecast_staffing.xlsx`:
- **Forecast_Staffing** — date-level forecast volume, required/available
  FTE, staffing gap
- **Summary** — model accuracy comparison, weekly rollup, monthly rollup,
  all in one place
- **Charts** — all 3 charts together (required-vs-available FTE, weekly
  gap, monthly volume-vs-required-FTE combo)

Then run `03_generate_summary_ppt.py` to build the 6-slide summary deck,
`final_output/usecase2_forecast_summary.pptx` — every number on it is
pulled straight from the Excel output, not hand-typed.

**Known result on the shipped synthetic data** (so you know what to expect,
not a guarantee if you change the random seed/config): Holt-Winters beats the
naive-seasonal baseline (18.8% vs 20.1% holdout MAPE), and the occupancy
target is now derived from the roster's real average shrinkage (~20.6%,
~79% occupancy) rather than a flat assumption — the 40-agent roster runs
short by an average of ~2.5 FTE, peaking at 3.7 FTE short on the worst day,
over the next 6 weeks — a believable, actionable "we're tight, not in
crisis" story. If you regenerate the data and the model ever loses to the
baseline, the script's own `assert` will stop you before you present a
false "the model is better" claim — that's intentional, see
`narration_script.md` for how to talk about it either way.

## Metadata.rtf content (paste this into Metadata.rtf before upload)
**Task**: Build a daily contact-volume forecasting model and translate it
into required agent staffing (FTE), compared against current roster
availability and real roster shrinkage.
**Apps used**: VS Code (Python), Microsoft Power BI Desktop.
**Request / scenario**: As a data analytics consultant, forecast customer
care contact volume for the next 6 weeks from ~3.8 years of daily history
(with trend, weekly/yearly seasonality, holidays and campaign spikes), then
convert the forecast into required agent FTE (using real roster shrinkage)
and flag staffing gaps against the current roster.
**Flow**: Generate/ingest 3.8 years of volume history + agent roster (incl.
shrinkage %) → exploratory decomposition (trend/seasonality) → naive
baseline forecast → Holt-Winters exponential smoothing model → validate on
a holdout (fails loud if the model doesn't beat the baseline) → forecast
forward 6 weeks → convert to required FTE via handle time + real
shrinkage-derived occupancy → compare to available roster hours → export
one Excel workbook (3 sheets, 3 charts) → build a Power BI report and a
summary PowerPoint deck for the staffing narrative.
**Output**: `final_output_forecast_staffing.xlsx` (Forecast_Staffing,
Summary, Charts sheets), `usecase2_forecast_summary.pptx` (6 slides), plus
a Power BI report (3-4 visuals) built live on screen.

## Notes on scope / assumptions (say this out loud if asked)
- Forecast is built at the total-daily level for clarity in a single
  walkthrough; a production rollout would model each LoB/channel series
  separately — the output file still carries enough detail to slice by LoB
  in Power BI from the raw input if needed.
- Staffing conversion uses `hours = volume × AHT / 3600`,
  `FTE = hours / (shift hours × occupancy)`, where occupancy is now derived
  from the roster's real average shrinkage rather than a flat constant. A
  full rollout would use Erlang C for service-level-driven staffing — noted
  as a next step, not built here, to keep the walkthrough explainable on
  camera.
